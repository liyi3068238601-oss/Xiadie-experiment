# CYR.2C 任务工作台 UI 设计（聊天计划卡 / 编辑器增强 / 恢复面板）

- 版本：v0.1
- 日期：2026-08-04
- 状态：待评审（对应功能设计 [CYR.2C spec](../superpowers/specs/2026-08-04-cyr2c-agent-planner-recovery-design.md)）
- 设计语言继承：`xiadie-unified-ui-prototype` v0.1（深色玻璃、灰紫主色 `#9587c9`、紧凑头部、卡片、状态 pill）
- 适用范围：三个新增/增强界面及其状态；不改变既有信息架构
- 交互原型：`prototype/index.html`（桌面 / 移动两档预览）

## 1. 设计原则

- 陪伴感优先：克制、安静、有呼吸感，不把任务台做成传统后台管理系统。
- 状态信号用小面积呈现：色带、圆点、pill；锁定、失效、风险都不能只靠颜色传达，必须配图标与文字。
- 计划是"先可见、可修改、可批准"的产物：所有会改变计划内容的操作都有明确入口和可撤销路径。

## 2. 聊天紧凑计划卡

出现在遐蝶回复气泡之后，作为独立卡片，不混入正文气泡。

### 结构

```text
┌ 候选计划 · 待确认 ──────────────┐
│ 目标摘要（一行截断）             │
│ 4 步骤 · 2 依赖 · 3 来源 · 需批准 │
│ 1. 梳理现有检索流程              │
│ 2. 定位失败点 ← 依赖 1           │
│ 3. 设计改进方案 ← 依赖 2         │
│ +1 更多                          │
│ [进入工作台编辑]   [取消]         │
│ 确认后创建任务草稿，不会自动开始   │
└─────────────────────────────────┘
```

- 头部：eyebrow「候选计划」+ 状态 pill「待确认」。
- 统计行：步骤数 / 依赖数 / 来源数 / 批准要求（`需批准` / `无需批准`）。
- 节点预览：最多 3 条（序号、标题、依赖标记 `← 依赖 N`），超出显示 `+N 更多`。
- 底部操作：主按钮「进入工作台编辑」、次按钮「取消」。
- 说明文字固定为「确认后创建任务草稿，不会自动开始执行」。

### 状态

| 状态 | 视觉 | 动作 |
|---|---|---|
| 生成中 | 卡片骨架屏 + 「遐蝶正在整理步骤…」 | 无 |
| 待确认 | 完整卡片 | 进入工作台编辑 / 取消 |
| 已进入编辑 | 折叠为一行：「计划已进入工作台编辑中」+ 链接 | 点击回到对应运行 |
| 生成失败 | danger 色边框 + 可读原因 | 再试一次 / 放弃 |
| 已取消 | 淡出，聊天内保留「已放弃该计划」摘要 | 无 |

## 3. 工作台计划编辑器增强

### 3.1 运行详情头部

- 在「编辑计划」旁新增次操作「重新生成计划」。
- 点击后弹出确认层：文案「重新生成会保留 N 个已锁定节点，未锁定节点可能被改写」；确认后进入生成状态。
- 生成中：编辑器区域显示骨架节点 + 「正在生成候选计划…」。
- 生成失败：danger 色横幅显示可读原因 + 「重试」。
- 生成成功：编辑器载入候选计划；锁定节点保持且视觉标记不变，用户审阅后走既有保存路径。

### 3.2 节点卡片锁定控件

- 锁定按钮位于节点卡片标题行右侧，18px 线性锁图标。
- 状态三态：
  - 未锁定：空心锁；hover 变实心并提示「锁定此节点」。
  - 编辑自动锁定：实心锁 + 浅灰紫 pill「已锁定 · 编辑」，tooltip「你编辑过此节点，重新生成时不会改动」。
  - 显式锁定：实心锁 + pill「已锁定」，tooltip「重新生成时不会改动；解锁后可被改写」。
- 锁定节点视觉：左侧 2px 灰紫色带 + 轻微 tint 背景；正文保持可读，不做强玻璃嵌套。
- 解锁：直接解锁并 toast「已解锁，重新生成时可以改写此节点」；解锁不需要二次确认（低风险、可逆）。

### 3.3 来源引用呈现

- 节点卡片底部「来源」行：类型 chip，`类型图标 + 短标签`（记忆片段 / 记忆集 / 知识 / 对话）。
- hover / focus 显示有界摘要 tooltip。
- 失效引用：danger 色 chip「来源已失效」+ 删除线标签 + tooltip 显示失效原因。
- 运行级横幅（任一失效引用）：danger 色，「有节点引用已失效，无法开始执行；请移除失效引用或重新规划」，仅一个入口「处理失效引用」（定位到第一个失效节点）。

### 3.4 重新生成确认层

- 标题：「重新生成计划」。
- 说明：列出锁定保留规则 + 已锁定节点数 + 「未锁定节点可能被改写」。
- 按钮：主「生成候选计划」、次「取消」。

## 4. 恢复面板

### 4.1 位置

- 运行详情页：run 处于 `paused` / `recovery_required` / `failed` 时显示「恢复」区域。
- 应用中断时，运行详情顶部显示 warn 横幅：「应用中断，任务已进入保护状态，不会自动继续」，动作：继续 / 重新规划。

### 4.2 结构

```text
┌ 恢复建议 · 风险:中 ─────────────────┐
│ 最后证据                              │
│ 工具：search_workspace               │
│ 阶段：executing · 状态：interrupted  │
│ trace：ab12… · 错误：已脱敏          │
│ [继续] [重试（还剩 2 次）] [重新规划] │
└─────────────────────────────────────┘
```

- 头部：「恢复建议」+ 风险 pill：`side_effect_free`=低（绿）、`idempotent`=中（黄）、`side_effectful`=高（红）。
- 最后证据：最近一次 ToolRun 行（工具名、阶段、状态、`trace_id` 可复制、脱敏错误）。
- 动作按恢复矩阵启用/禁用：
  - `side_effect_free`：继续 / 重试 / 重新规划。
  - `idempotent`：继续 / 重试（显示剩余次数，上限 3）/ 重新规划。
  - `side_effectful`：继续（需确认）/ 重新规划；无终态证据时只允许重新规划，禁用按钮附原因。
- 空态：无 ToolRun 记录时显示「当前运行没有工具执行记录；接入工具后将在这里显示恢复建议」。

## 5. 组件规格

| 组件 | 规格 |
|---|---|
| 计划卡 | 圆角 12px，弱玻璃，状态 pill 在头部右侧 |
| 节点卡 | 圆角 10px，左边框 2px 状态色带，hover 提亮边框 |
| 来源 chip | 圆角 6px，8–9px 文字，类型图标 13px |
| 风险 pill | 沿用 `--ok` / `--warn` / `--danger`，圆点 + 文字 |
| 横幅 | 圆角 10px，左侧 3px 色带，`--danger` / `--warn` 低饱和底 |
| 锁定图标 | 18px 线性 SVG，激活态实心 + 灰紫柔光 |
| 主/次按钮 | 沿用 unified prototype 的 primary / ghost 规格 |

## 6. 响应式

- 桌面（>1080px）：聊天计划卡 ≤520px，工作台编辑器保持三列可用。
- 窄窗（900–1080px）：右栏隐藏；编辑器节点操作收敛到「更多」菜单。
- 移动（<640px）：计划卡单列全宽；节点锁定按钮保留但 tooltip 改为长按提示或折叠进更多；恢复面板纵向堆叠，动作按钮全宽。

## 7. 无障碍

- 锁定、失效、风险状态必须同时有图标、文本标签和 `aria-label`，不依赖颜色单独传达。
- 「重新生成计划」、锁定按钮、恢复动作全部可键盘聚焦操作（Tab + Enter）。
- 生成中/失败/空态均提供可读文本，不用闪烁动画承载信息。

## 8. 与功能 spec 映射

| UI 组件 | 功能合同 |

| 聊天计划卡 | SSE `plan_proposal` 事件、`POST /api/task-runs/from-proposal` |
| 重新生成计划 | `POST /api/task-runs/{run_id}/planner-proposal` + 既有 `PUT /plan` |
| 锁定控件 | `task_nodes.user_locked` / `locked_reason` |
| 来源 chips 与失效横幅 | `task_node_source_links` 失效 fail closed |
| 恢复面板 | 三类恢复语义矩阵与 ToolRun 证据 |

## 9. 验收

- 实施后的真实页面与原型逐项对照：结构、状态、文案一致。
- 前端源契约测试覆盖：计划卡状态流转、锁定三态、失效引用横幅、恢复矩阵按钮可用性。
