# CYR.2C 任务工作台 UI 设计（基于当前产品 UI）

- 版本：v0.2
- 日期：2026-08-04
- 状态：待评审（对应功能设计 [CYR.2C spec](../superpowers/specs/2026-08-04-cyr2c-agent-planner-recovery-design.md)）
- 设计语言继承：当前产品前端 `frontend/src/styles.css` 设计系统——深紫 `#7c5cff`、幽蓝 `#45c7ff`、银白、玻璃拟态、圆角 `16px/10px`、柔光；组件命名与 `TasksPage.tsx`、`ChatView.tsx` 现有类名一致
- 适用范围：三个新增/增强界面及其状态；不改变既有信息架构与设计系统
- 交互原型：`prototype/index.html`（桌面 / 移动两档预览）

## 1. 设计原则

- 沿用当前设计系统，不引入第二套视觉语言；新组件全部使用现有 tokens、圆角、玻璃与字号体系。
- 状态信号用小面积呈现：色带、圆点、pill；锁定、失效、风险不能只靠颜色，必须配图标与文字。
- 计划是"先可见、可修改、可批准"的产物：所有会改写计划的操作都有明确入口，生成结果可审阅后再保存。

## 2. 聊天紧凑计划卡

作为 `.msg.assistant .bubble` 内部的一块卡片，复用聊天中已有的内嵌卡片模式（参照 `knowledge-grant-card`：独立玻璃卡、eyebrow 头、圆角 16px）。

### 结构

```text
┌ 候选计划 · 待确认 ───────────────────┐
│ 梳理知识库检索流程并输出改进方案        │
│ 4 步骤 · 2 依赖 · 3 来源 · 需批准      │
│ 1 梳理现有检索流程                     │
│ 2 定位失败点    ← 依赖 1               │
│ 3 设计改进方案  ← 依赖 2               │
│ +1 更多                                │
│ [进入工作台编辑]      [取消]           │
│ 确认后创建任务草稿，不会自动开始执行     │
└───────────────────────────────────────┘
```

- 头部：cyan `page-eyebrow`「候选计划」+ 右侧状态 pill（复用 `.task-run-status` 样式）。
- 统计行：步骤 / 依赖 / 来源 / 批准要求，`--text-faint` 小字。
- 节点预览：最多 3 条（序号方块 + 标题 + 依赖标记），超出显示「+N 更多」。
- 操作：主按钮「进入工作台编辑」（渐变紫）、次按钮「取消」（描边）。
- 固定说明：确认后创建任务草稿，不会自动开始执行。

### 状态

| 状态 | 视觉 | 动作 |
|---|---|---|
| 生成中 | 卡片骨架屏 + 「遐蝶正在整理步骤…」 | 无 |
| 待确认 | 完整卡片 | 进入工作台编辑 / 取消 |
| 已进入编辑 | 折叠为一行摘要 | 点击回到对应运行 |
| 生成失败 | danger 边框 + 可读原因 | 再试一次 / 放弃 |
| 已取消 | 降透明度，保留「已放弃该计划」 | 无 |

## 3. 任务工作台增强

### 3.1 运行头部与"重新生成计划"

- 在 `.task-actions` 的「编辑计划」旁新增「重新生成计划」按钮（同尺寸、同 `--violet` 弱底样式）。
- 点击后弹确认层：文案「重新生成会保留 N 个已锁定节点，未锁定节点可能被改写」；确认后进入生成状态。
- 生成中：`.task-run-panel` 显示骨架节点 + 「正在生成候选计划…」；失败：danger 横幅 + 重试；成功：载入候选，锁定节点保持，走既有保存路径。

### 3.2 节点锁定（`.task-node` / `.task-plan-node`）

- 锁定按钮：节点标题右侧 18px 线性锁图标（复用 Icon 体系），hover 变实心。
- 三态：
  - 未锁定：空心锁；
  - 编辑自动锁定：实心锁 + pill「已锁定 · 编辑」；
  - 显式锁定：实心锁 + pill「已锁定」。
- 锁定节点视觉：左侧 2px 灰紫带（`.doing .task-item` 同款）或节点边框 tint；正文保持可读。
- 解锁直接生效并 toast「已解锁，重新生成时可以改写此节点」；解锁可逆，不需二次确认。

### 3.3 节点来源引用

- `.task-node` 底部「来源」行：`source-ref-chip`（类型图标 + 短标签）：记忆片段 / 知识 / 对话。
- hover/focus 显示有界摘要 tooltip。
- 失效引用：danger 色 chip「来源已失效」+ 删除线 + 原因 tooltip。
- 运行级横幅（任一失效引用）：danger 色（左 3px 色带 + 低饱和底），文案「有节点引用已失效，无法开始执行；请移除失效引用或重新规划」，入口「处理失效引用」定位第一个失效节点。

### 3.4 计划编辑器锁定

- `.task-plan-node` 标题行右侧加锁按钮；编辑任一输入（标题 / 验收 / 依赖）即自动置为锁定并显示「已锁定 · 编辑」pill；提供显式锁定/解锁按钮。
- 依赖选择与保存逻辑不变（`expected_revision`、`PUT /plan` 仍是唯一写入入口）。

## 4. 恢复面板

### 4.1 位置

- `.task-run-panel` 内新增「恢复」区块：run 处于 `paused` / `recovery_required` / `failed` 时显示。
- 应用中断时顶部显示 warn 横幅：「应用中断，任务已进入保护状态，不会自动继续」。

### 4.2 结构

```text
┌ 恢复建议 · 风险:中 ──────────────────┐
│ 最后证据                              │
│ 工具 search_workspace · interrupted   │
│ trace ab12cd34… [复制] · 错误（已脱敏）│
│ [继续] [重试（还剩 2 次）] [重新规划]  │
└──────────────────────────────────────┘
```

- 风险 pill：`side_effect_free`=低（`--ok`）、`idempotent`=中（`--warn`）、`side_effectful`=高（`--danger`）。
- 最后证据：最近 ToolRun 行（工具、阶段、状态、`trace_id` 可复制、脱敏错误）。
- 动作按恢复矩阵启用/禁用（见功能 spec §9）：无终态证据时只允许重新规划并附原因。
- 空态：无 ToolRun 记录时显示说明文字。

## 5. 组件规格

| 组件 | 规格（沿用现有值） |
|---|---|
| 计划卡 | 圆角 16px，玻璃渐变底，cyan eyebrow，右上门状态 pill |
| 运行横幅 | 圆角 10px，左 3px 色带，`--danger` / `--warn` 低饱和底，10px 文案 |
| 节点卡 | `.task-node`：圆角 7px，左边框 2px，8–10px 字号 |
| 来源 chip | 圆角 6px，8px 文字，类型图标 12px |
| 风险 pill | `--ok` / `--warn` / `--danger`，圆点 + 文字，9px |
| 锁定图标 | 18px 线性 SVG，激活态实心 + 灰紫 |
| 主/次按钮 | 沿用 `.task-create button` / `.task-actions button` 体系 |

## 6. 响应式

- 沿用现有断点：`1180px` 隐藏右栏、`900px` 侧栏收为图标、`640px` 底部导航。
- 移动端：计划卡全宽；节点操作收敛到「更多」；恢复动作按钮全宽堆叠；`header-meta` 隐藏。

## 7. 无障碍

- 锁定、失效、风险状态同时有图标、文本标签和 `aria-label`，不依赖颜色单独传达。
- 「重新生成计划」、锁定按钮、恢复动作可键盘聚焦操作。
- 生成中/失败/空态均为可读文本，不用动画承载信息。

## 8. 与功能 spec 映射

| UI 组件 | 功能合同 |
|---|---|
| 聊天计划卡 | SSE `plan_proposal` 事件、`POST /api/task-runs/from-proposal` |
| 重新生成计划 | `POST /api/task-runs/{run_id}/planner-proposal` + 既有 `PUT /plan` |
| 锁定控件 | `task_nodes.user_locked` / `locked_reason` |
| 来源 chips 与失效横幅 | `task_node_source_links` 失效 fail closed |
| 恢复面板 | 三类恢复语义矩阵与 ToolRun 证据 |
